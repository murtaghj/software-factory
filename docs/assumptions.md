# Assumptions

Local-development defaults that stand in for organisation-only decisions. Each one names the
decision-register entry (docs/spec/15-decisions-sources.md) it stands in for. None of these closes
a decision-register entry; every referenced entry remains `proposed`/open.

| ID | Package | Stands in for | Assumption | Revisit when |
| --- | --- | --- | --- | --- |
| A-01 | W-002 | INT-04 (Temporal hosting), INT-07 (database provider), ADR-11 | Local podman compose services: Temporal CLI dev server 1.9.1 (server 1.32.0) and PostgreSQL 18.6, pinned by digest. Managed Temporal and the production database are not selected. | W-001 inventory |
| A-02 | W-002 | ADR-11 | Node 24.22.2 is pinned through fnm + `.node-version`; pnpm 12.16.1 through corepack. TypeScript is pinned to 6.0.3, not 7.x, because typescript-eslint 8.72.1 supports `<6.1.0`. | typescript-eslint supports TS 7 |
| A-03 | W-004 | INT-01 (first application, build/test commands), INT-09 (trace backend) | The fixture system runs its services in-process (node:http) against a throwaway Postgres database per environment, instead of container images. Release "images" are pinned as exact source digests. Traces go to an in-memory collector rather than an observability backend. Fixture callers identify themselves with an `x-customer-id` header, not OIDC. | W-001 inventory / W-038 telemetry adapter |
| A-04 | W-006 | INT-07 (database provider, credentials, backups) | Local login roles `factory_migrate_login` (NOINHERIT, may only SET ROLE factory_migrator) and `factory_app_login` (inherits factory_runtime) with fixed local passwords. Each test suite gets a throwaway database on the compose Postgres 18.6. Backup/restore qualification is not attempted. | W-001 inventory; W-056 backup/restore |
| A-05 | W-007 | INT-07 (object storage, encryption, retention) | Artifacts use `FileObjectStore`, a local filesystem store with hard-link conditional promotion, instead of an S3-compatible service; no encryption at rest. Reservation TTL defaults to 1 hour, download capabilities to 5 minutes, retention to 365 days. Sweeps run as a separate `factory_retention` job role (BYPASSRLS, column-limited grants in migration 0013). The reference DDL names that job role but does not define it. | W-001 inventory; W-056/W-055 retention and storage qualification |
| A-06 | W-008 | W-005 architecture/access review; INT-06 (OIDC issuer, organization roles, workload identity) | A local ES256 OIDC test issuer (`startTestIssuer`) serving a real JWKS over HTTP. Each trusted issuer is bound to exactly one organization; the organization is never taken from a token claim or payload. Bearer tokens only (no browser session/BFF yet). Roles follow the chapter 12 matrix. `membership.application_scope` holds application IDs or `"*"`. Application ownership also comes from `owner_ids`, matched against the principal ID or token groups. Viewers cannot read `restricted` artifacts and only operators can read `sensitive_session` artifacts. A task's creator or owner cannot authorize its release. | W-005 review; W-001 inventory |
| A-07 | W-008 | W-005; ADR-12 | Capability grants are minted only from the stage role: read/workspace_write on the allocation's own workspace (plus repository-scoped read telemetry for discovery). No stage role ever receives a publish, merge, deploy or credential grant; those effects go through controller workflows. Audit `details_ref` holds a small factory-generated reason object rather than an artifact ref. | W-021 capability proxy and execution profiles |
| A-08 | W-009 | W-005; W-063 routing; W-064 drafts; W-144; W-137 security intake; W-050 mixed work | Intake fails closed with explicit 422 codes for capabilities not yet built: new-application targets, design scope or designSource, security/embargo metadata, and parent/child tasks. `changeClass` defaults to the work type (no recipe or path classifier yet). Incident priority requires an operator or application_owner role on the primary application. An idempotency record past its 7-day window still answers by the same rule (replay if the hash matches, 409 if not) until retention deletes it. | Each owning package |
| A-09 | W-010 | INT-04 (Temporal hosting, worker versioning) | Dispatcher tests use the Temporal TypeScript SDK `TestWorkflowEnvironment.createLocal()` (CLI dev server). The worker build ID recorded on `workflow_binding` is `unversioned` until Worker Deployment versioning is configured. The dispatcher enumerates organizations through the intentionally unscoped lookup and works per tenant without a principal, so embargoed outbox rows would be invisible to it. Embargoed intake is refused in M1 (A-08), so none exist. | W-001; W-137 embargo qualification |
| A-10 | W-011 | W-029 investigation template; W-063 template routing; W-013 policy | M1 runs a fake investigation plan template `investigation 0.1.0` (scope → investigate → evidence_review → deliver → close) with a fake runner Activity that produces real finalized output artifacts and schema-valid StageResults. The policy snapshot is the fixed `m1-default-policy` revision 1 until W-013. No template exists yet for other work types: resolvePlan fails closed with `no_compatible_template`. | W-029 / W-063 |
| A-11 | W-013 | W-097 adoption spikes; ADR-21 (OPA or Cedar policy engine) | No policy-engine adoption decision exists. Per chapter 22 ("The current specification is the fallback"), policy is bundled hand-written TypeScript in `packages/policy`, pinned with the workflow. Risk path rules are a local default set (auth, payments, migrations, contracts/OpenAPI, deploy, pii) over the spec's organization-default trigger names. Fake stages estimate and charge 1 USD unless configured. Active-time and calendar ceilings are evaluated but not yet metered (no real runner). | W-097 report; W-021/W-035 usage metering |
| A-12 | W-014 | INT-04/INT-07 retention policy | Event retention defaults to 30 days. A cursor before the first retained event gets 410 EventCursorExpired. Retention is judged by `recorded_at` within the window, because no runtime or retention role may delete `task_event` rows. Streams poll every 250 ms, send keepalives every 15 s and re-check authorization every 15 s. The dashboard ships as tested components plus a live client; the SPA shell and OIDC PKCE sign-in are not built yet. | W-032/W-067 dashboard; W-055 retention |
