# Assumptions

Local-development defaults that stand in for organisation-only decisions. Each one names the
decision-register entry (docs/spec/15-decisions-sources.md) it stands in for. None of these closes
a decision-register entry; every referenced entry remains `proposed`/open.

| A-17 | P-09 (docs/plan-additions.md) | W-005 role model; W-013 budgets; INT-14 provider billing | Per-developer allowances are outside the reference DDL: forward migration 0014 adds `principal_allowance` (one row per principal and UTC calendar month) and `budget_account_allowance` (which allowance a task account draws on, fixed when the account opens). The creator pays, even if ownership later changes. A principal with no allowance row is not enrolled and is limited only by task budgets; this is a deliberate opt-in default, so an organization that wants everyone capped must enrol everyone. An enrolled principal's next month opens with the same limit. A task that starts in one month keeps drawing on that month's allowance. Only `organization_admin` sets a limit (`POST /v2/principals/{id}/allowance`); anyone reads their own (`GET /v2/me/allowance`). A used-up allowance refuses new tasks with 429 `allowance_exhausted` (no Retry-After header is sent) and ends running tasks incomplete. Amounts are the fake runner's configured costs until real metering exists. | W-005 review; real usage metering (W-021/W-035) |

| A-21 | P-24 (docs/plan-additions.md) | W-032/W-067 dashboard; W-005 role model | Two routes and one table outside the rev 1.13 contracts and reference DDL: `GET /v2/me/queue` (the ranked "what needs you next" list, `schema: factory-queue/1`, hand-mirrored in `packages/client`, never in `packages/contracts`) and `POST /v2/me/queue/acks` (`{ key }` -> 204; 404 for a key that is not the caller's current item, 409 `not_dismissible`, 422 `invalid_key`, 503 when a source could not be read), plus forward migration 0015 `queue_ack` (append-only, forced row security, a person reads and writes only their own rows). Ranking is server-side only: tier (blocked on you, about to run out, stopped, finished), then incident-priority first, then soonest deadline, then longest waiting, then key. Thresholds: a review request is "about to run out" within 24 hours; an allowance within 10 percent of its limit; a stopped or finished task drops off by itself after 14 days. "Mark as seen" is one person's view state, not a command: it changes no task and has no undo; tasks `failed`, `incomplete` and `succeeded` are terminal, so it is the only way out of tiers 3 and 4 before 14 days pass. Each source runs in its own SAVEPOINT with a statement timeout (2 s); a source that fails, times out or returns an item for a project the caller cannot read is reported `degraded` and the rest still answer. `GET /v2/me/work` and the boards are unchanged. The MCP tool `factory_my_work` is read-only and there is no ack tool; `factory work seen` needs an interactive terminal. | W-032/W-067; owner answers to the open questions in plan-additions P-24 |
| A-22 | P-24, P-01, P-07 (docs/plan-additions.md) | W-005 role model; INV-21, INV-29 | "Only a person marks an item as seen" and "only a person answers a decision" are conventions of the clients, not rules the API can enforce: the CLI and the MCP server both send the developer's own `FACTORY_TOKEN`, so an agent that holds that token can call `POST /v2/me/queue/acks` and `POST /v2/decisions/{id}/responses` directly. The CLI asks for an interactive terminal and a typed confirmation (`approve`, `seen`); the MCP server has no such tool. Neither stops a determined agent. Planned fix: a separate agent token that the API refuses on those two routes. Until then treat both as guard rails against mistakes, not as a security boundary. A-21 adds, from review: an allowance notice's key includes the limit, the budget source reads without writing and on the queue's clock, and a source is timed out on the JS side as well as by the database (its late queries are refused). The source time limit relies on pg's per-client first-in-first-out query queue (a query in flight finishes before the savepoint rollback); node-postgres deprecates queueing a query behind another for pg 9, so revisit this when pg is upgraded. `asOf` and the `stale` check were not built because no outside source exists. | W-005; P-24 open item on an agent token |
